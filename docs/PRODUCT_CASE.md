# 产品判断与三分钟演示

## 问题定义

在真实供给不变的前提下，用更清楚、更相关的卡片信息帮助用户判断是否适合自己。推荐系统决定推荐对象，本作品重点讨论表达层如何协同。

店铺卡帮助选商家，商品卡帮助选交易对象。店铺人均消费不是套餐售价，券面额不是支付金额，图片活动价不能代替实时交易报价。

## 从截图到可检验假设

| 观察 | 不直接下的结论 | 试验方向 |
| --- | --- | --- |
| 蛋挞图片出现20元，卡片出现18.99元 | 不认定谁对谁错，可能是时效或资格差异 | 图片剥离易过期价格，金额由独立报价提供 |
| 代金券图片出现180代200，卡片显示174元 | 不把面额、素材价、当前售价混为一谈 | 200元作为券面额，174元作为示例售价 |
| 店铺卡有人均20元，也有15.9元促销商品 | 不用低价单品代替店铺消费口径 | 保留人均参考，商品入口单独展示 |
| 多款产品同图展示，部分素材有“3选1” | 不推断一单包含所有图片中的商品 | 若扩展此类案例，必须保留选择关系与规格 |

除前三类结构性观察外，不将用户截图周边个人信息带入仓库。交互案例中的店名、套餐、服务能力和优惠资格全部为虚构假设。

## 技术选择

封面图：多模态理解 / OCR / 选图 / 裁剪 / 受控图像编辑。优先真实素材，不生成额外份量和不存在的装修。

标题：信息抽取 + 品类模板 + 受约束改写。锁定店铺身份、商品、人数、规格。

推荐理由：证据检索 + 卖点表达 + 场景化选择。用户需求影响呈现顺序，不创造服务事实。评价保留意见属性，不能覆盖商品规则。

价格行：语言模型辅助理解复杂规则；金额与资格由权威交易服务和确定性程序决定。当前演示使用整数分，故意把模型排除在金额计算之外。

## 当前实现与生产方案

当前为完整的规则交互演示，包含真实计算、候选约束、人工校验、错误回退和记录导出。图片预先生成，非实际商家素材。图货核验通过标签模拟，不声称运行了视觉检测。可选服务端语言模型仅选择已核实候选编号，未连接外部付费提供方验收。

生产方案需要接入授权商家/商品资料、真实报价、证据版本与有效期、评价筛选与实时失效机制。上线应按品类渐进测试，而非一开始自由生成全部素材。

## 人机协作与实际取舍

1. **资料边界。** 识别截图包含与答题无关的个人信息，因此只提炼卡片观察，未上传原图；使用独立生成素材。
2. **事实边界。** 不凭截图断言价格错误，建立明确的虚构实验数据；不把低价单品、券面额和人均价混用。
3. **模型边界。** 模型负责表达选择；金额、有效性和候选合法性由独立程序控制。自由文本不因“人工填写”就绕过规则。
4. **实测修正。** 浏览器操作发现输入98元后卡片仍可能保留旧金额，将价格同步改为输入时即时重算并复测98、128、168元及异常路径。
5. **交付优先级。** 主体是一个可解释的实验工作台，不扩展账号、商家管理或假数据增长仪表盘。

## 验证设计

先在同等流量条件下比较现有表达、确定性模板、基于证据的AI表达。第一轮仅改变副标题，保持召回、排序、卡位与优惠不变。再用同一个合格候选池验证场景化选择增量。

用户稳定随机分组；依据基线、最小可检测增量及核销周期确定样本与时间。核心看每千名入组用户在约定观察窗口内的已核销且未退款订单，兼看平台总订单，排除入口转移。点击和支付转化用于诊断；退款、投诉、图货不符、价格不一致、延迟是护栏。业务增量需覆盖推理、审核和售后新增成本。

## 三分钟脚本

**0:00—0:35：定义问题。** 首页卡片在有限空间帮助用户理解供给。打开蛋挞案例，指出图片价格与卡片价格可能有口径差异，不能仅凭截图判错。展示保留商品主体、数量和独立售价。

**0:35—1:05：技术与取舍。** 点击四元素解释。说明图像、语言模型、规则引擎各自适用位置。切到代金券案例，展示200元面额和174元售价分开表达。

**1:05—1:45：用失败证明机制。** 打开双人套餐，128元减10元为118元；把价格改为98元，不能减券；切到过期状态，按商品价展示；报价失效则不沿用旧值。

**1:45—2:15：人机协同。** 选择带娃需求，展示有证据的儿童餐椅；移除证据后理由失效。在审核框填“全城第一，免费停车”，展示拦截。人负责补证和判断，而不是替AI盖章。

**2:15—3:00：回到业务。** 打开验证页，运行实际规则自检。解释为什么不能只看点击率，并说明用模板作为对照、观察有效核销和成本。最后明确当前规则演示与未来真实模型/数据接入的差别。
